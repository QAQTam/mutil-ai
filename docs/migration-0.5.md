# Upgrading from 0.4.x to 0.5.0

0.5.0 fixes how the normalization layer pairs tool results with assistant tool
calls. The pairing rules tightened in 0.4.0 were stricter than this document
stated and dropped real tool output, which made models re-answer the same user
turn on every tool round.

Use `mutil-ai = "0.5"` (or `cargo add mutil-ai@0.5`) when upgrading.

## Source compatibility

- `NormalizeAction` gains three variants: `ReconciledToolResultId { name, from,
  to }`, `FlattenedToolCallIntoText { name }` and `FlattenedToolResultIntoText {
  name }`. Exhaustive matches over `NormalizeAction` must handle them.
- `NormalizeStats` gains `reconciled_tool_result_id`, `flattened_tool_call` and
  `flattened_tool_result`. Build it with `NormalizeStats::default()` plus field
  updates, or add `..Default::default()` to existing struct literals.
- `Message`, `ChatRequest`, `Part`, adapter entry points and `Error` are unchanged.

## Tool pairing now keys on the call id

A tool result that carries a call id pairs with the pending call holding that id.
The tool name is no longer part of that test; after pairing, the result's name is
reconciled to the call's name, as it was in 0.3.x.

```rust
use mutil_ai::{ChatRequest, Message, Protocol, ToolCall, ToolResult, normalize};
use serde_json::json;

let request = ChatRequest::new([
    Message::assistant_with_tools("", [ToolCall::new("lookup", json!({})).with_id("call_1")]),
    // The result keeps the correct id but a blank or display-only name.
    Message::tool_result(ToolResult::new(Some("call_1".into()), "", "real output")),
]);

let (clean, report) = normalize(&request, Protocol::OpenAiChat).unwrap();
// 0.4.0/0.4.1: the result was dropped and replaced by an error result reading
// "missing tool result". 0.5.0: the real content survives.
assert!(report.is_clean());
```

Histories that depended on the old drop are affected: a mismatched name no
longer hides tool output from the provider.

## Explicit ids still never fall back to names

The 0.4.0 security boundary is intact. A result carrying an id that matches no
pending call is not matched by name; it goes through
`NormalizeOptions::orphan_tool_result` (default `Drop`), and the unmatched call
gets a synthesized error result.

One narrow case is now tolerated: if the call's id was **generated by the
current `normalize` call** — because the stored assistant tool call had no id —
the result may pair with it by name, since a generated id such as `call_1`
cannot equal the provider id the result still carries. The result's id is then
rewritten to the call's id so the wire format stays self-consistent, and the
repair is reported as `ReconciledToolResultId`:

```rust
use mutil_ai::{NormalizeAction, normalize, ChatRequest, Message, Protocol, ToolCall, ToolResult};
use serde_json::json;

let request = ChatRequest::new([
    Message::assistant_with_tools("", [ToolCall::new("lookup", json!({}))]),
    Message::tool_result(ToolResult::new(Some("call_0".into()), "lookup", "real output")),
]);

let (_, report) = normalize(&request, Protocol::OpenAiChat).unwrap();
assert!(report
    .actions
    .iter()
    .any(|a| matches!(a, NormalizeAction::ReconciledToolResultId { from, to, .. }
        if from == "call_0" && to == "call_1")));
```

Generated ids are assigned per `normalize` call and are not a durable identity.
Persist the id the provider issued so pairing does not depend on this fallback.

## Diagnostics

Tool parts stored on a `User` or `System` message are still rendered as literal
text — `"Orphan tool result from ..."` / `"Unpaired tool call ..."` — but the
rewrite is now recorded as `FlattenedToolResultIntoText` / `FlattenedToolCallIntoText`.
A history that mixes tool output into a user turn therefore stops reporting
`is_clean() == true`, which is the signal to move that output into a `Role::Tool`
message instead.

## What did not change

- Defaults stay `orphan_tool_result: Drop` and `missing_tool_result: Synthesize`.
- Duplicate and empty/duplicate call ids are still rejected.
- Anthropic and Gemini still merge adjacent same-role messages and place tool
  results in the user turn.
- Transport, authentication, retry, streaming and response-limit behavior from
  0.4.0 is untouched.
